# 数据契约 · 规则在哪

> **本文件不是规则，是版本日志。** 规则真源在仓库根目录 [`数据方法与契约.md`](数据方法与契约.md)，请优先读它。
>
> | 要查什么 | 看哪份 |
> |---|---|
> | 数据怎么拉、怎么检查、失败怎么办（**规则**） | `数据方法与契约.md` |
> | 当前做到哪一步、待补项、历史改判 | `数据契约落地台账.md` |
> | 参考项目对照与证据 | `数据层对照清单.md` |
> | 规则是否被遵守、发布是否放行 | `scripts/validate-contract.py` → `contract-check.json` → `scripts/release-gate.py` |
> | 哪一版做了什么 | 本文件（倒序） |
>
> **给后续维护者 / AI**：执行取数、校验、发布、排障一律以规则文件为准；本文件下方所有 `# vX.Y` 小节只记录当时做了什么，**不构成规则、不得据以改写规则**。台账里的「待补」表示尚未达标，不是许可。规则变更须单独改规则文件并说明原因。
>
> **发布纪律**：打包与三条自动链在提交前必须跑门禁；`gate != pass` 一律不提交，不用「沿用上次真值」当绿灯。门禁的 advisory gaps 对应台账 P1/P2 待补，只提示不阻断；待补清空后可启用 `--strict`。

---

> **界面样式规则**：`界面样式契约.md`（颜色单一真源、按钮样式、切换与重绘、门禁）。
> 本文只是版本日志，`数据契约落地台账.md` 只是落地状态，均**不是规则**。

# 首页版部署包（ETF + 可转债）

## v50 · 每周自动更新，主站在 Netlify（云端为主、体检中心备用）

**架构**：GitHub Actions **每周五收盘后**用无头浏览器打开**已经部署好的 Netlify 主站**，点两套系统原有的「一键更新行情」，把新交易日真正写进本机后，读出两个行情补丁，生成仓库根目录的 `state.json` 并推回仓库 → Netlify 自动重新部署 → 任何人打开站点，`common/hub-core.js` 自动把 `state.json` 补回本机并重放补丁。**主系统一行代码都不用改**（v47 的随包状态自动生效机制直接复用）。

一句话：**取数在云端，数据跟着仓库走，手机不再需要存任何东西**。之前「存不下、清本机就倒回 10-29、换网址多一份旧账、手机占空间」这几个问题，从根上一起消失，而且站点地址固定。

### 三步部署

1. **GitHub 建仓 → 把本文件夹全部文件传上去**（网页端 `Add file → Upload files` 即可，公共电脑不用装 git）。
   - **已传过上一版（v49）的话，只需替换 4 个文件**：`.github/workflows/update.yml`、`scripts/update.mjs`、`README.md`、`GitHub拉数据_主站在Netlify_说人话说明.md`，其余文件逐字节未动。随附的 `每周版_覆盖用4个文件.zip` 解压后路径就是仓库根目录；网页端建议打开已有文件点铅笔编辑整段粘贴，不要新建隐藏目录。
   - 仓库建议设为 **Public**：公开仓库的 Actions 分钟数不计费，私有仓库每月 2000 分钟。
   - `Settings → Actions → General → Workflow permissions` 选 **Read and write permissions**（脚本要推 `state.json`）。
2. **Netlify 连接仓库**：`Add new site → Import an existing project → GitHub → 选这个仓库`。
   构建命令 / 发布目录都**留空**，`netlify.toml` 已写好（`publish = "."`）。部署完拿到 `https://xxx.netlify.app`。
   - **不能用拖拽发布**：拖拽只发静态文件，Actions 推的 `state.json` 不会进站点，整条链路断掉。
3. **填站点地址**：GitHub 仓库 `Settings → Secrets and variables → Actions → Variables → New repository variable`
   - Name `SITE_URL`，Value 填 `https://xxx.netlify.app`（不带尾斜杠，不放 Secrets，它不是密钥）
   - 然后 `Actions → 每周行情同步 → Run workflow` 手动跑一次，看日志确认。

### 数据怎么流

```
GitHub Actions（每周五 17:37 北京时间，一次补齐整周）
  → 无头 Chrome 打开 Netlify 主站，点上「一键更新行情」
  → 只认「补丁里出现更晚的行情日期」为成功（HTTP 200 / 提示文字都不算）
  → 生成 state.json → git push
  → Netlify 自动重建 → 网页打开自动补回本机、刷新日期
```

**每周一次为什么够**：两套系统的更新逻辑都是「从当前数据末日的下一天，一直抓到今天」，不是只补最后一天。一次点击会把本周 5 个交易日全部补齐；某周漏跑了，下周也会把两周的缺口一起补上。

`netlify.toml` 给 `state.json` 加了 `Cache-Control: no-store`，**避免 CDN 把新日期缓存成旧日期**——这是最容易踩的一处。

### 云端为主，数据体检中心退为备用

**正常流程里，不需要再手动到体检中心点更新。** 周五自动跑完，周末打开站点就是本周完整数据。体检中心里的「一键更新行情」保留，定位是备用手段，不删、不改。

**「所有数据都在 GitHub 拉」这句话要说准**：数据不是 GitHub 的服务器自己去拉的。Actions 只是按时启动一个无头浏览器、替你点系统页面里那个按钮，**真正发请求、解析字段、写补丁的仍是页面里原来那套取数代码**。所以源站认不认这台云机房的 IP，决定这周能不能取全：

- 东财（两套行情）、腾讯 / 新浪（ETF 兜底）、上交所（脚本补 `Referer`）：正常可取
- 深交所、乐咕：之前自检是「200 但没数据行」，云机房 IP 不保证解开；取不到就明写「保留原值」，**不写假数据、不提交、不倒退**

反过来说，备用手段有它独有的价值：**手机直连走的是你家宽 / 运营商 IP，跟云端机房 IP 不同**，云端被拦的源，手机手动点可能反而通。两边数据不会打架——v47 的机制是「本机缺的才补、本机更晚的不覆盖」，所以备用更新取到的数据会留在这台设备，不会被云端较旧的快照盖掉。

**一处必须说清**：备用手段取到的数据**只落在本机**，不会自动写回仓库，别的设备打开站点看不到。想让全站都吃到，走下面「手动兜底」那条：导出离线包 → 替换仓库 `state.json` → 提交。只有这台设备需要的话，不动也没关系。

### 省额度

- 已经改成**每周最多一次构建**（周五），比每天跑省得多
- 没取到更晚的行情就**不提交、不触发构建**（节假日、源站全挂时零消耗）
- 取数计算全在 GitHub Actions，**不花 Netlify 积分**；也不用 Netlify Function，不占函数调用额度
- 想再省或想更勤，改 `.github/workflows/update.yml` 里 cron 一行即可；`workflow_dispatch` 手动跑不额外产生定时消耗

### 手动兜底（云端被源站拦时，体检中心作备用）

手机或任意能上网的设备上「一键更新行情 → 导出整站离线包」→ 解压取出里面的 `state.json` → 在 GitHub 网页端替换仓库根目录同名文件 → 提交 → Netlify 自动重部署。格式见 `scripts/state.example.json`（**每个值必须是字符串**）。这条不依赖云 IP 能不能取到数。

### 老实说的几条边界

- Actions 出口是 GitHub 云机房 IP。**乐咕、深交所可能仍被反爬拦**，自检那两个「200 但没数据行」不一定因此解开。跑完看 Actions 日志：没取到的一侧会明写「保留原值」，**不会假装成功、也不会把日期倒退**
- 交易所逐日剩余规模、公告增量的解析仍在页面里，Actions 只是驱动页面，不另写一套
- 首次跑之前主站得先能打开（用包内 10-29 基线部署一次即可），形成闭环
- 上交所那道 Referer 墙由脚本只对 `sse.com.cn` 请求补 `Referer` 解决；其它源请求头保持原样
- 回测引擎、策略参数、11 个数据文件一个字节没改

> 文件末尾 v48 的「Netlify 取数转发端（Function）」章节保留作备选，本仓库**默认不启用**：`common/health-config.js` 里 `base` 为空，所有请求照旧直连。两条路不要同时开。

## 离线缓存（全站 Service Worker）

- 根 `sw.js` 注册在**站点根作用域**，覆盖首页、两个系统、各工具页；旧的 `/etf/sw.js` 会自动注销，不会两套 SW 抢控制权。
- 首次打开任意顶层页：SW `install` 先并发装入 34 个小文件（页面 / CSS / JS / 图标 / sw.js / README），随后页面侧在后台串行预取 6 个 `.gz`（约 28 MB）写入 Cache Storage，共 40 条。不阻塞首屏，首页出现「✓ 页面与主要数据已缓存」即表示可离线，同时右侧出现「导出整站离线包」按钮。
- 之后所有静态资源 **cache-first**；腾讯 K 线、东财、扶摇、jsDelivr、飞书字体等跨域请求一律放行，不缓存、不拦截。
- `.gz` 入库时统一去掉 `Content-Encoding` / `Content-Length` 头，配合页面已有的 gzip 魔数兜底，兼容「服务器自动二次压缩」与「原样返回」两种托管行为。
- 离线时**能用**缓存行情跑回测、看策略 / 组合 / 体检历史结果，本机 patch 也还在；**不能**一键更新行情、交易日历、体检（这些本来就需联网），联网后自动补上。
- 检测到新版本时顶栏右侧出现「检测到新版本 · 点击刷新」。**改任何页面或数据文件后**：把 `sw.js` 与 `common/header.js` 里的 `CACHE` 末段同时 +1（当前 `wufu-all-v0.60`，两处已对齐），整包重拖，老访客强刷一次。
- SW 只在 **HTTPS 或 localhost** 生效；`file://` 双击请用全量单文件版。

## 导出整站离线包

首页缓存提示行右侧的「导出整站离线包」按钮，**只在预缓存就绪后出现**。点一次由 `common/export.js` 完成：

1. 遍历当前版本 Cache Storage 的全部同域条目，按原路径写入 zip（页面、组件、6 份 `.gz`、图标、manifest）。
2. 补上 `sw.js`、`README.md`（这两个不在缓存清单里），再写入 `state.json` —— 导出瞬间的**全量 localStorage**（策略、策略组合、行情增量、修复记录、交易日历、标的池、分组、体检记录）。
3. 附带 `restore.html`（状态恢复页）、`START-Windows.bat` / `START-Mac.command`（本地静态服务器）、`README-OFFLINE.txt`、`export-manifest.json`。

zip 是 **store 模式**（浏览器内自拼，不引外部库），约 32 MB。**没有把 32 MB 内嵌进单个 HTML**，所以不需要改任何页面、引擎或数据块。

- **本地离线跑**：解压 → 运行启动脚本（需 Python 3）→ 浏览器开 `http://localhost:8765/index.html`。**不要直接双击 index.html**，`file://` 下读不到 gz。
- **恢复本机状态**：localhost 是新站点，本机数据为空。打开 `restore.html` 点「恢复本机状态」，把 `state.json` 写回后再进首页，策略和行情增量都在。
- **重新部署**：把解压后的文件夹（或这个 zip 本身）整包拖回花生壳 / Netlify 即可；多余的 `state.json`、`restore.html`、启动脚本不影响线上运行，线上不要点 `restore.html`。
- **安全**：扶摇 API Key 只存会话内存，**不导出**，离线包里需到 ETF 体检页重新填写。
- 导出的是**当前缓存快照**；线上改版后重新导出一次即可。断网时若缓存未齐，导出的包会缺文件，等首页出现缓存提示后再导更稳。

## 择时管理：趋势均线 / 估值温度

- **判定指数已扩展为全部统一基准**：两套系统「择时管理 → 状态判定指数」都读 `/common/index.gz` 的 27 支（A股 18 / 港股中概 4 / 海外 4 / 转债等权 1），按来源分组、可折叠可搜索，A股组默认展开。CB 页原来只有 3 支，本次补齐；ETF 页原本就是全量。
- **可转债系统新增「估值温度」判定方式**（`mmTypeSel`，默认仍是趋势均线，不影响任何既有策略）：
  - 温度指标只用现有字段：**平均转股溢价率 / 平均纯债溢价率 / 平均收盘价**；换手率等覆盖不全的字段不纳入。
  - 每日横截面**有效样本 ≥ 100 只**才记温度；按实测自 **2018-12-07** 起可用，更早及样本不足日不触发、维持原状态。
  - 温度 = 当日指标在**截至当日**的 N 日历史分位（默认 250 日，无前视）；≥ 过热分位（默认 80）连续 N 日进入走弱，≤ 冷却分位（默认 20）连续 M 日恢复；走弱时按「降至仓位 X%」整体缩放权重，仍走 T+1 调仓日。

- 推荐先试：`250日 / 过热80 / 冷却20 / 降至50%`（改动很小）；想明显压回撤用 `降至0%`，代价是收益也下降。实测双低轮动：基线 112.01%，降至0% 为 94.32%、最大回撤 -27.44% → -18.73%。这是历史表现，不是保证。
- 策略保存 / 导出会带上 `mm_type / temp_metric / temp_win / temp_hi / temp_lo`，导入后自动还原判定方式。

## 内置策略「三要素50」与基准国证2000（v27 修正版）

**可转债内置策略已换版**：旧的「双低轮动-10只(价格+溢价率)」下架，新增内置策略 **「三要素50」**。老访客强刷后，本机策略库里 v27 的旧内置项会一次性升级成新版（只认未改动过的内置指纹；用户自己保存/改过的同名策略不会被覆盖）。

策略口径（来自禄得网截图 + 本次指定参数）：

| 项 | 值 |
|---|---|
| 持仓 / 卖出 | 买入排名 1–50 名；**已持有标的跌出第 60 名才卖出** |
| 打分因子 | 转股溢价率（负相关，权重 1）、剩余年限（负相关，权重 1）、到期收益率（正相关，权重 1） |
| 排除因子 | 收盘价 < 95、收盘价 > 140、剩余年限 < 1 年 |
| 基础排除 | 已满足强赎条件、公告提示强赎、公告到期赎回、已公告强赎、排除 ST、上市不足 3 天 |
| 其他 | 等权持仓、因子标准化「稳健」、默认交易成本、区间 2017-01-03 ~ 2026-10-29 |
| 基准 | **国证2000 `399303.SZ`**（CB 主数据块内 2383 日全覆盖） |

**买卖缓冲现在用「持有区间 1–50 + 跌出第 60 名才卖」表达**（v28 改法）：

- 「持有排名区间」填 **1–50** → 只新买前 50 名
- 「卖出条件」选 **「跌出第 N 名才卖」= 60** → 把卖出边界从 50 放宽到 60，51–60 名的旧持仓继续留着
- 这个下拉项原为「排名名次 ≥ N」（命中即提前卖），v28 起改为「跌出排名才卖」：**只放宽持有上界、不提前卖**；当日停牌/数据缺失的持仓也不会被它误卖。引擎里名次条件不再走「命中即卖」，而是参与 `bandOut` 上界计算（取 `max(rankM, N)`）
- 「买入附加条件」留空
- 仍是零新增输入框、零新增策略参数；这次动的是卖出条件的语义与引擎判定

**三点如实说明**：

1. 截图「排除赎回状态」列出 5 项，其中 **「公告实施强赎」此前已按你的要求删除**，本系统没有该开关；其余 4 项全部按截图勾选。
2. 截图没有给出「基础设置」页，**调仓周期 v29 起改为「每周一」（v27/v28 为每交易日 1 日）**、因子标准化按系统默认「稳健」。这两项若与原策略不同，直接改策略参数即可。
3. 系统权重按「持有排名区间长度」计算，本策略为 **50**；跌出 60 才卖只影响卖出边界，不改变目标权重分母。候选不足 50 只时剩余仓位由兜底资产（默认现金）补齐；51–60 名只是已持有标的的缓冲区，不会被新买入。

「三要素」中的到期收益率 = 系统基础因子 `ytm`（静态条款 + 当日收盘价实时折现）；剩余年限 = `remain_y`；转股溢价率 = `prem_now`。三个因子都在包内，不依赖联网。

## 持仓权重：新增「因子加权」

两套系统「持仓权重」下拉都加了 `因子加权（按得分比例）`，默认仍是原来的等权，**既有策略与回测数字一律不变**。

- **做什么**：轮动策略选出 Top N 后，不再 `1/N` 平分，而是按本期**综合得分的排名分位**归一分配——排名越靠前配得越多。
- **为什么用排名分位而非原始得分**：系统内 `score` 已按因子 `direction` 统一成越大越好，但可能为负、量纲随期漂移、偶尔出现极值；排名分位恒正、抗极值、只用当期截面（无前视）。得分缺失的标的排最后。
- **单只上限 `2/N`**：超出的部分按原比例回分给未封顶标的，防止一只吃掉大半仓。
- **作用范围**：仅轮动策略生效；再平衡用的是它自己的「再平衡权重模式」，本下拉不影响。只持 1 只时各模式结果相同（面板会提示）。
- 参数字段 `holding_weight = "factor_score"`，随策略保存 / 导出 / 导入还原。旧版本页面读到这个新值会安全回退等权，不会报错。

实测（当时的内置预设、含默认成本）：ETF「低波ATR轮动-11资产」13.76% → 11.06%；可转债「双低轮动-10只」8.27% → 8.00%。只持 1 只或再平衡预设两种模式结果相同（因子加权仅轮动生效）。**这是方法生效的证明，不是「更好」的结论**：因子加权是排名信息的放大器，池子小、调仓频繁、成本敏感时会放大换手与噪声；可转债末态还会因高权重标的未成交而留更多现金，建议与等权对拍后再决定用不用。

## 因子现状（供扩展参考）

- **剩余年限 `remain_y`**：已是现成基础因子。**v28 起按发行条款推算的契约到期日计算**（`起息日年份 + 票息期数`，月日取付息日；`(契约到期日 − 当日)/365.25` 自然日），不再用日历下标折算；超出回测日历的债也能算出正确剩余年限。无条款字典的 65 只老债回退旧 `WUFU_CBEXPI` 下标口径。注意条款里的 `e` 是**实际终止日**（含提前强赎），若拿它算会引入前视，故不采用。
- **剩余规模 `remain_scale`**：已随 `cb/data/cb-extra.gz` 提供，深沪两口径合成，**交易所日频变化点** 975 只 / 71482 点；基线静态，日历外新点用「更新剩余规模（日频）」导入（见下文）。
- **到期收益率 `ytm`**：已随 `cb/data/cb-extra.gz` 提供，986 只条款字典 + 当日收盘价实时折现求 IRR。**条款静态，但数值随「一键更新行情」追加的交易日自动延伸**；新纳入个券若缺条款字典返回空值，需整包重抓。

## 已知边界

- 覆盖到官方已公布的未来交易年份（当前 2027-12-31）；每年 11 月国办发布次年放假安排后，进数据体检中心的任一体检页点一次「一键更新交易日历」自动延伸。
- 跨系统组合按日期取共同区间并归一化，「总收益」与单系统里跑出来的不会逐值相同，这是口径不是错误。
- 组合页提供固定权重与净值动量轮动；系统内组合还支持自定义任意因子轮动，两者功能等价、数值口径不同。

- 老策略若还没有曲线快照，进各自系统打开一次「我的策略」即按最新行情补齐。
- 本机策略、组合、行情 patch、Cache Storage 按域名存储；换设备或清浏览器数据后需重新缓存一次、并用各系统「导出 / 导入」搬数据。「导出整站离线包」会把这些状态一并带走，是这个手工流程的一键版本。

## 新增基础因子：剩余规模 / 到期收益率

`cb/data/cb-extra.gz`（约 401 KB）随整包缓存，页面加载完 `cb-vol.gz` 后串行载入，挂在 `window.__CB_EXTRA`；加载失败时两个因子返回空值，不影响回测。

- **剩余规模(亿)** `remain_scale`：未转股余额，**深沪两种口径合成，均已升级为交易所日频**。

  - **沪市** = 东财 `ACTUAL_ISSUE_SCALE`（发行规模，亿元）×（1 − 上交所累计转股比例%），数据来自上交所转股统计（`COMMON_SSE_ZQ_TJSJ_ZXTJ_KZZZGLSTJ_L` / `COMMON_SSE_SJ_ZQSJ_KZZZGTJ_L`，51421 行 / 500 只沪市债 / 2000-07 ~ 2026-11-11）。上交所**只报有转股发生的交易日**。

两者都在「因子管理 → 基础因子」下拉，窗口固定 1，阈值量纲分别为「亿」与「%」。原有 6 个行情 gz 与引擎主逻辑未改动。

### 剩余规模的限制条件（重要）

1. **深市是逐交易日、沪市是事件日**：深交所按交易日公布未转股余额（开市前统计，T+1）；上交所只在**有转股发生**的交易日产生记录，无转股日不产生点。两市都 forward-fill 到每个交易日，无新记录的交易日值是沿用上次，不是当日实测。
2. **沪市是反推值，不是直接余额**：`发行规模 ×（1 − 累计转股比例）`。用比例而非「累计转股股数 × 转股价」，避免下修 / 调整转股价造成偏差。累计比例出现回落时按历史最大值单调修正；比例 ≥100% 或余额 ≤0 记空值。
3. **首次记录之前返回空值**，不用发行规模冒充；东财无发行规模记录的老代码（100xxx / 111xxx 等）同样为空值。
4. **两种口径的采样节奏不同**：深市逐交易日、沪市事件日。跨市比较时请留意这点。
5. **基线静态、日历外增量单独导入**：不随「一键更新行情」的日频增量同步。点数据体检中心的 **「更新剩余规模（日频）」** 读取同域 `cb/data/cb-scale-daily.json`（整包重传时刷新），或导入本地快照；结果写本机 patch 的 `p.scale`。上交所 `commonQuery.do` 与深交所 `ShowReport/data` 都校验 Referer，浏览器跨域直连会被拒，**无法在网页里自动联网抓取**，这是做成同域快照导入的原因。增量文件 `asof=2026-11-11`，含 49 只债 / 102 个日历外变化点。
6. **部分个券沿用旧月末点，不是日频**：共 54 只（深市 6 只接口返回空明细、沪市 44 只匹配不到发行规模、4 只仅有日历外数据），构建时保留其 v24 月末序列作为兜底，不产生空值也不倒退；用这些个券做日频分析时要留意。
7. 到期收益率未计强赎、下修、回售等提前退出条款，属持有到期的理论值；条款字典静态，价格实时。

## v28：剩余年限按真实到期日 + 「跌出第 N 名才卖」

### 1. 剩余年限修好

旧实现把「到期日」存成**回测日历里的下标**，日历只到 2026-10-29，超出日历的 506 只债被统一截到末日下标 2382。算 `(2382 − 当日下标)/243` 时，越靠近末尾减出来越小，最后一年这 506 只全被算成「不到 1 年」，于是命中「剩余年限 < 1 年排除」被误杀、策略空仓——**它们其实大多还有 2–5 年才到期**。

v28 改为读 `cb/data/cb-extra.gz` 的条款字典（986 只覆盖），用 **起息日 `v` 的年份 + 票息期数 `cp.length`、月日取付息日 `p`** 推算契约到期日，按 `(契约到期日 − 当日日期) / 365.25` 计算年数；条款缺失的 65 只老债回退旧下标口径。主因子与 `cbFactorVal` 两处计算已同步。

> 为什么不用字典里的 `e`：实测 986 只里 429 只 `e` 与推算一致，557 只 `e` **早于**推算日（提前强赎/回售后的实际摘牌日，最多早约 5 年），0 只晚于。若用 `e`，等于让系统提前知道「这只债将来会哪天被强赎」，属前视偏差，而且会把强赎债伪装成短债、重新制造误排除。推算值完全来自发行条款，**无前视**。

口径从「243 交易日/年」换成「365.25 自然日/年」，因此**所有用到剩余年限作筛选或打分的策略，历史数值会变**；未使用该因子的策略逐值不变。三要素50 同时用了它做筛选与打分，回测结果会变，属预期。

### 2. 卖出条件「排名名次 ≥ N」改为「跌出第 N 名才卖」

旧语义：名次 ≥ N 就**额外卖出**（叠加在「跌出持有区间就卖」之上，方向是提前卖）。
新语义：把卖出边界从 `rankM` **放宽到 N**（`sellRankM = max(rankM, N)`），`srk > N` 才卖；只放宽、不收紧、不提前卖。卖出面板里 `type:"rank"` 的条件不再走「命中即卖」，其它卖出条件（持有天数、止盈止损、因子判断等）行为不变。

买入附加条件与不卖条件面板里的「排名名次 ≤/≥ N」**保持原义不变**；ETF 系统两份页面当时**未改动**（本次仅可转债系统）——**已于 v32 同步**，见文末。

三要素50 因此改回直接配法：`rank_n=1, rank_m=50`、`buy_add=[]`、`sell_conds=[{type:"rank", op:"gte", value:60, enabled:true}]`，即「买前 50 名、跌出第 60 名才卖」。

### 旧机制为什么会一直报

v30 的「数据截止一致性」用两条启发式跳过老债：契约到期日落在日历内，或落后 ≥60 个交易日。于是**刚退市、行情停在最近的债**（截图里剩的那 9 只，落后 4~59 日）既没到期、又没满 60 天，会一直报「没跟上最新日期」；随着日历一天天延长，先报两个月才自动消失。以后每有一只债退市，都要重演一次。

### 新机制：生命周期表，每次体检按当前数据重算

新增 `lifeMap(D)` + `endOf(c, arr)`，8 项检查统一使用：

- 每只债记「最后有效收盘价」所在交易日。
- 满足任一条件即判为**已结束**：① 契约到期日已过（`WUFU_CBEXPI` 下标 < 日历长度）；② 最后有效日之后连续 **≥5 个交易日**没有新行情。
- 「数据截止一致性」直接跳过已结束标的；落后 1~4 日原本就不计命中，所以**从退市第一天起就不会报**。
- 其余 7 项检查的扫描上限统一截到最后有效日，终点之后的 `null` / `-1` / 价格静止 / 四价矛盾一律不算问题。
- 判定**可逆**：行情若补回来，最后有效日会前移，该债自动回到「在市」。不需要手工名单、不需要改包、不需要标记已确认。

注意：已结束标的**在生命周期内的真实错误仍然会报**，只是终点之后不再报；在市标的的检查口径完全没变。

## v46 · 更新数据真正存得下（大仓库）

**问题**：手机给网页的 localStorage 只有约 5MB，按整个网址算总账。可转债近千只债的
每日增量 + 修复包 + 撤销备份越攒越厚，v45 的「压缩 + 清旧快照」只是延缓，
写满后依然存不下；v45 只是把「假成功」改成弹红字，并没解决容量本身。

**做法**：把大块数据从 5MB 小本本搬进浏览器自带的大仓库（IndexedDB）。

- 小键（策略、设置、日期）仍走 localStorage，行为不变
- 大键（行情增量 patch、修复包、撤销快照）改存 IndexedDB，容量通常是几十 MB 起
- 同步读写靠内存镜像 + localStorage 里的压缩兜底，业务代码不用改成异步
- 打开页面时自动把老版本留在 localStorage 里的大值搬进大仓库，并把小本本里
  那几 MB 换成几十字节的标记，**第一次写新数据就把空间腾出来**
- `WufuStore.flush()`：一键更新收尾会等所有大仓库写入真正完成才报「已存入」，
  写失败弹红字，不再出现「显示成功、重开回 10-29」
- 「清除本机更新」「撤销」会同时清两边，导出整站离线包仍包含全部增量

**失败兜底**：若浏览器完全禁用存储（无痕/隐私模式、部分 App 内置 WebView），
会明确弹红字提示关闭无痕模式，不会静默丢数据。

**边界**：这是纯前端方案，不需要后端、不需要电脑、不需要 Netlify 积分。
包里 11 个 .gz 数据文件、回测引擎、策略参数均未改动。

**部署**：整包重拖，别只传 index.html；老访客强刷一次。CACHE = wufu-all-v46。

## v0.68.1 · 数据源按资产族收敛为 3 条链 + 美股 ETF 静态基线（2026-11-17）

**结论：上游源统一不了一个，也不该统一；统一的是落库契约与失败策略。**

统一不了的四个硬理由：
1. 历史起点不同：东财美股 ETF 起于 QQQ 2001 / XLV·XLP 2005 / TQQQ 2011 / BTAL 2011；Yahoo 可到 1999。文章 1999–2011 段东财补不出。
2. 复权口径不同：美股 ETF 分红多（XLV 102 次、XLP 107 次），Yahoo 给 adjclose + 分红事件；东财用前复权。混用同一字段会对不上。
3. 出口不同：境外源只在 GitHub Actions 出口通，本机/平台侧被挡；压成一家等于把整条周更链挂在一个源上。
4. 本地 11 个 `.gz` 含退市债与全历史截面，零抓取，外部源无法替代。

**三条链（按资产族，不按接口）**

| 链 | 上游 | 产出快照 | 抓取 |
|---|---|---|---|
| L | 本地 gz | `cb-daily.json` / `index-daily.json` | 零 |
| A | 东财 + 申万官网 | `industry-daily.json` / `market-amount.json` / `us-etf-daily.json` | 周度 |
| G | Yahoo + CBOE | `gold-daily.json` | 周度 |

**统一契约**：每份快照带 `chain`（L/A/G）、`contract: "chain/1"`、`source`、`dataAsOf`、`warnings`；失败时保留上次真值并写 warnings，绝不用占位值补位。前端仍只读小 JSON，用起来就是一个源，维护点收敛到 3 处。

**编排**：`update.yml` / `refresh-dashboards.yml` 把三条链拆成独立 step，每步 `if: always()`，一条链红灯不阻断其它链写回；`scripts/merge-chain-status.py` 汇总 `external-warnings-{L,A,G}.json` 成前端读的 `external-warnings.json`（含 `byChain`，可看出哪条链沿用真值）。提交步 `if: always()` 兜底，避免以前「一个源红灯 → 后面整步跳过 → 本地快照没提交」的耦合缺陷。

**回补（A：2012 → 今，只用东财，不新增源）**

`us-etf-daily.json` 为 5 只美股 ETF 的日线静态基线：

| 标的 | 东财 secid | 区间 | 根数 |
|---|---|---|---|
| XLV | 107.XLV | 2012-01-03 → 2026-11-16 | 3739 |
| XLP | 107.XLP | 2012-01-03 → 2026-11-16 | 3739 |
| QQQ | 105.QQQ | 2012-01-03 → 2026-11-16 | 3738 |
| TQQQ | 105.TQQQ | 2012-01-03 → 2026-11-16 | 3738 |
| BTAL | 107.BTAL | 2012-01-03 → 2026-11-16 | 3662 |

共同交易日 3660 天，文章主段 2012–2024 可直接用本基线做年度再平衡回测。列为 `d/o/c/h/l/v/a`（日期、开、收、高、低、量、额），东财前复权 `fqt=1`。
`scripts/build-us-etf.py` 首次全量、之后只读已有 JSON 从各自末日 +1 追加，不重算历史；单只失败保留真值并写 warnings。
